Secure Proxy Failover Lab

A client sends its traffic out through a gateway and 20 exit proxies. Click a proxy to crash it. Click again to bring it back.

This page is a simulation. It follows the same rules as the real lab (same pools, same health check timing, same retry behaviour), but nothing here is a real proxy. The real thing runs in Docker and is tested on every push: code · test runs.

Things to try

  1. Crash one proxy. A request or two takes a second longer while the gateway retries somewhere else. Nothing is blocked.
  2. Crash the primary pool. A request may get dropped while the gateway notices, then the four reserve proxies take over.
  3. Crash all 20. There is no way out, so traffic is blocked. It does not fall back to a direct connection. "Leaked" stays at 0.
  4. Revive all. Proxies have to pass two health checks before they get traffic again.
  5. Flip the kill switch. Everything is blocked instantly, even with all 20 proxies healthy.
Timing used here matches the lab's gateway config: health check every 1s, 2 misses to mark a proxy down, 2 passes to bring it back, 1s connect timeout, up to 3 retries on a different proxy.
